# Publication Checklist

Run this checklist before making a project public or adding new material.

## Confidentiality

- [ ] No employer, customer, supplier, or employee confidential data.
- [ ] No internal field names, endpoint names, screenshots, or architecture diagrams.
- [ ] No personal contact information or identity documents.
- [ ] No restricted competition data or submission files.
- [ ] No copied code with unclear ownership or incompatible licensing.

## Technical Quality

- [ ] The project runs from a clean environment.
- [ ] Tests cover the main path and relevant failure paths.
- [ ] Sample data is synthetic or licensed for redistribution.
- [ ] Error handling and logging do not expose secrets.
- [ ] CI passes on the supported Python versions.
- [ ] The README states limitations and non-goals.

## Narrative Quality

- [ ] The business problem is understandable to a non-specialist.
- [ ] The author's contribution is explicit and accurate.
- [ ] Metrics describe what was measured, not what was hoped for.
- [ ] The project explains at least one meaningful trade-off.
- [ ] No company branding is used without permission.
